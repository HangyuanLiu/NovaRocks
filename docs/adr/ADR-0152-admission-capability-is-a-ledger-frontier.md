## 问题

后端的准入账本会遗忘旧决定。那么一个前端要凭什么证明「我这次请求不是在重放一条你已经忘掉的决定」——而且这个证明必须在后端持续遗忘的同时仍然开得出来？

## 背景与执行事实

准入（admission）是 BE 对 FE 的背压闸门：FE 每次要在某个 BE 上开一段工作，先申请一张准入票，BE 同意才开始。因为网络不可靠，FE 在收不到回复时的唯一安全动作是**原样重发**，所以 BE 必须记住「这个 operation 我已经决定过了，答案是 X」。这份记忆就是账本（`AdmissionTicketAuthority` 的 `acquisitions`）。

账本有界，旧记录会被回收。回收之后就出现了本条 ADR 的问题：一个找不到记录的 operation，究竟是**新的**，还是**一条被忘掉的重放**？两者的正确处理相反——前者要接纳，后者必须拒绝，否则同一个 operation 被准入两次。

下表是这条链上的四个量，以及它们各自的变化节奏。**节奏是这条 ADR 的全部要害**：

| 量 | 谁拥有 | 变化频率 | FE 如何得知 |
|---|---|---|---|
| 账本记录 | BE | 每次准入 | 不得知 |
| 回收（reclaim） | BE | 挂在 deadline 自检上，**100 毫秒**一次 | 不得知 |
| 保留期（`replay_retention`） | BE 配置 | 常量，默认 **120 秒** | 不得知 |
| 准入凭据（`AdmissionEpochCapability`） | BE 发布 | 见下 | **只经心跳**，测试 500 毫秒 / 生产 1000 毫秒 |

关键的不对称：**BE 改变自己状态的时钟比 FE 学习它的时钟快 5 到 10 倍**。任何"FE 必须持有 BE 的当前值"的设计在这里都不成立——那不是竞态窗口（意味着大多数时候能赢），而是结构上赢不了。

另一处必须先知道的耦合：FE 的拓扑成员身份（`revision_members`）决定拓扑修订号，而修订号是冻结查询计划的校验依据。凭据一旦进入成员身份，凭据的变化就等价于「集群改变了形状」，会让已经在跑的 attempt 失败。

做对了的正例锚点：`reap_locked` 按**终态顺序**回收（`terminal_acquisition_order` 是 FIFO），所以「已被遗忘的集合」天然是一个前缀，可以用一个下界来表达——这正是本条裁决得以成立的前提。改这块代码前先读它。

## 考虑过的选项

**A. 一个不透明的当前值，相等比较**（原实现，**设计否决**）。BE 每次回收就重铸一个随机值；FE 带着它上次学到的值来；不相等就拒。机制最简单，不需要任何额外状态，而且它对安全性是充分的。否决理由不是它不安全，而是它要求「FE 持有 BE 的当前值」——上表已经说明这个前提在任何有持续流量的集群上都不成立。这是设计否决：只要回收挂在一个比心跳快的时钟上，它就永远不成立，而把回收改慢会让账本的有界性失效。

**B. 单调水位线，仍然是 FE 回声值与 BE 当前值比较**（**设计否决**）。把随机值换成递增计数，比较从 `!=` 改成 `<`。这是最容易被重新提出的改法，**它不解决任何问题**：FE 回声 5、BE 已到 8，`5 < 8` 照样被拒。比较运算符从来不是症结，症结是被比较的两端都在动。

**C. 已回收 operation 的墓碑集合**（**成本否决**）。BE 记住自己忘掉了哪些 `TaskOperationId`，只拒绝这些。安全性质一条不丢，语义也最直白。代价是引入第二份有界状态，而它一旦淘汰，就回到同样的问题——只是把边界推远一格，并没有取消它。代价变化的触发条件见「何时重新评估」。

**D. 凭据表达账本的下界**（采纳）。凭据携带两样东西：**签发者**（issuer，进程身份）与**位置戳**（stamp，账本进展）。签发者相等比较；位置戳与 BE 的**回收前沿**（reclaim frontier，已回收记录中最高的位置戳）比大小。请求要证明的命题是「我的 operation 命名于账本遗忘的一切**之后**」，位置戳高于前沿就是这个证明。

D 为什么能成立而 B 不能：被比较的两端**节奏不同**。前沿只前进到已经终态满一个保留期的记录，因此它落后已发布位置戳整整一个保留期；而 FE 的回声最多落后一次心跳。120 秒对 1 秒，中间有两个数量级的余量。

对照过的外部系统：无。这是本系统自己的准入契约，没有可直接对照的实现。

## 裁决

采纳 D。凭据 16 字节拆为 8 字节 issuer + 8 字节 stamp，issuer 非零因而整体非零。

**开发规则**：

1. **凭据的两半用不同的比较方式，不要统一。** issuer 相等（别的进程的账本在这里什么都不说明），stamp 比大小（同一进程的旧凭据只是落后）。看到有人把整个凭据拿去相等比较，就是回到了选项 A。
2. **凡是"一端持续变化、另一端靠周期性学习"的值，不得用相等比较做准入判据。** 先比较两端的时钟；慢的一端结构上追不上快的一端。这条规则的适用范围不止准入。
3. **准入凭据不进入 operation 身份。** 它不是 operation 的属性，而是「FE 上次听到 BE 是什么时候」的属性。放进身份会让隔一次心跳的重放被读成冲突，而重放恰恰是规定的恢复动作。
4. **准入凭据不进入拓扑成员身份，冻结快照按"放置"比较而不是相等比较。** 账本前进不是集群改变形状。判据是 `places_the_same_work_as`：哪个槽位、由哪个进程填，才是冻结计划依赖的事实。
5. **账本写满时只拒绝眼前这一个请求，不动前沿。** 装不下不等于忘掉了；没有遗忘就没有凭据变得不安全，拒绝一个请求不是拒绝所有人在途工作的理由。

**调试规则**：

6. 看到 `admission epoch is sealed` 大面积出现，先量两个时钟——BE 的回收节奏与 FE 的心跳间隔——再看代码。这类症状的形状是「服务器起来一段时间后突然大面积拒绝」，那个"一段时间"约等于 `replay_retention`。

## 接受的妥协（诚实记录）

**安全边界从"任何被回收过的凭据"收窄为"位置戳落在前沿之下的凭据"。** 一个失联超过保留期的 FE 仍会被正确拒绝；但一个位置戳恰好高于前沿、而其 operation 的记录其实已被回收的请求，会被当作新请求接纳。这在当前实现里不可达——记录按终态顺序回收，前沿因此是遗忘集合的上界——但它是一条**由回收顺序保证的**性质，不是由类型保证的。若将来引入乱序回收（例如按大小或按 context 优先淘汰），这条性质立即失效，前沿就不再是有效判据。

**8 字节位置戳会饱和而不回绕。** 回绕会让戳跌回前沿之下，从而拒绝一切；饱和只是让一个已准入 2^64 次操作的 worker 无法再区分最后几次。选饱和是因为两种坏结果不对称，不是因为饱和本身正确。

**这不是选项 C 的语义。** C 能精确回答「这个 operation 被忘了吗」，D 只能回答「它是否可能被忘了」。我们接受了一个更粗但更省状态的答案，理由是省状态，不是理由更优。

## 何时重新评估

- **回收顺序不再是终态顺序时**（引入按大小、按 context 或按优先级的淘汰）——前沿不再是遗忘集合的上界，本条裁决的前提消失，应转向选项 C。
- **保留期被大幅缩短，或心跳被大幅拉长到同一数量级时**——余量消失，需要重新计算两个时钟的比值；比值小于约 10 倍就应重新评估。
- **选项 C 的成本下降时**（例如账本已经需要一份有界墓碑结构做别的事，边际成本接近零）——此时 C 的精确语义免费，应该采纳。
- **出现需要跨进程重放的场景时**（当前 issuer 相等比较直接排除了它）——那是一个本条 ADR 没有裁决的新问题。
