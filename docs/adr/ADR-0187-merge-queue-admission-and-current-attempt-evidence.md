## 问题

如何使合入队列的检查成为有明确来源、启用范围和原始材料的准入结论，同时让测试隔离生效？

## 背景与执行事实

原生执行和只读组合的责任继续遵守 ADR-0184、ADR-0186。工作流产生 GitHub 检查，组合库判断已取得的观测；源码构建失败也需要保留明确的失败结论。

| 实体 | 所有权与限制 |
|---|---|
| 合入队列 | 在准确合并组提交运行必需检查；队列及规则集配置是独立的仓库设置 |
| Admission 工作流 | 指定仓库/工作流、托管 runner 与准确事件提供正式来源；只读权限，无 secret |
| 准入入口 | 每次执行原生 cargo-only 链，保留退出与当前尝试，保存组合和摘要 |
| 启用声明 | 在原生常规集合内明确启用成员，逐项解释尚未纳入的范围 |
| 组合库 | 只读消费当前尝试，区分正式、演练与诊断，不建立跨运行证据存储 |
| Rust 批处理 | 提供成员、索引、真实退出、执行身份与清理事实；组合不改写原生结果 |

工作流文件已提交不证明规则集已启用；真实合并组检查与队列成功/拒绝路径仍需要部署后验证。

## 考虑过的选项

1. **每个 PR 和合并组都运行完整准入。成本否决。** 早期信号更充分，但同一修改支付两次完整 Rust 构建与测试；PR 上只提供独立快速预检。
2. **一次纳入全部常规单元。成本否决。** 覆盖直接完整，但尚未就绪的领域会阻断所有合入。采用原生集合内的显式启用范围，缺口可见。
3. **过滤掉隔离测试或忽略原生批处理非零退出。设计否决。** 前者改变执行集合，后者丢失批处理环境和收束失败；成员断言与批处理事实必须共同判断。
4. **用本地文件标志、干净 SHA 或环境变量充当正式证据。设计否决。** 它们可描述材料，却不具备合并组 GitHub 检查的来源权威。
5. **跨运行正式复用与持久证据服务。待评估。** 能节省运行成本，当前尚未提供存储和恢复责任；准入每次全部本轮执行。

## 裁决

1. **指定上下文。** 正式尝试只由准确仓库的 Admission 工作流，在托管 runner 的合并组事件或 main 手动事件中产生。校验 workflow ref/SHA、事件 head/base 与源码开始/结束记录。正式性的权威是 GitHub 检查，下载文件或伪造环境不授予该权威。
2. **启用与缺口一起报告。** 准入只对常规集合中的启用成员判断；未纳入、缺少纳入计划和原生列举缺口逐项保留。启用却未执行的范围阻断。声明缺失时恢复全部常规集合。
3. **按成员及批次共同判定。** 准入隔离只排除相应断言。Rust 聚合仍要求准确当前批次的成员观测和完整收束、成功清理、准备阶段成功且无环境错误或取消。原生退出与成员推导结论并列记录；独立或历史成员 PASS 不能合成该批次的成功。全量保持自身完整成员义务，不应用准入隔离；开发层聚合延后规则不变。
4. **失败也有材料。** 准备、列举或入口失败时保存失败组合、摘要、已观察退出和既有原始材料；未能列举不是空集合通过。当前尝试身份由其已确认观测提供，避免后续重新链接使此前真实观测失效。
5. **本地与上线分阶段。** 本地检查点之后，经授权发布/合入，建立正式 main 基线，授权启用规则集，再执行真实队列成功、失败及修复重新入队验收。缺后者不称门禁交付完成。

## 接受的妥协（诚实记录）

启用范围之外的回归暂时没有准入保护，必须在每次结论中可见。单一维护者无法自审，准入自身的改动依赖入队者审阅 diff；托管 runner 和只读权限不证明准入逻辑本身可信。每次准入重复执行全部启用成员，暂不节省跨运行成本。

Cargo doctest 的非零退出无法区分断言与构建/环境失败，在缺少原生分类时不能推导批处理通过。GitHub artifact 配置为有限保留期，尚非永久共享证据服务；未解决失败和正式引用须由维护者在到期前完成可恢复交接。本文描述代码合同，不声明远程设置或真实队列验收已经完成。

## 何时重新评估

- PR 流量、构建成本或早期反馈要求变化时，重评完整 PR 预检与队列并行/资源参数。
- 各领域在准入环境中建立 main 基线或有效处置后，逐步扩大启用范围；全部纳入后删除过渡声明。
- 有持久证据存储与明确恢复、保留 owner 后，评估跨运行正式同输入复用。
- 原生 doctest 执行方提供稳定失败分类后，重评其成员隔离及聚合资格。
- 维护者增多或外部贡献扩大时，重评工作流保护、审查与入队信任模型。
